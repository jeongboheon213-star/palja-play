# 유료 판매(LIVE) 전 체크리스트

> 이 문서는 운영 준비 목록이며 **법률 검토를 대신하지 않는다.** 아래 항목 중 법적 요건 판단이 필요한 것은 전문가(변호사·세무사) 또는 토스페이먼츠 가맹 심사 안내를 따라야 한다. 법률 검토 완료 여부: **미검토**.

상태 표시: ☐ 미완료 · ◐ 일부 · ☑ 완료

## A. 판매자·사업자 정보 (사이트 하단 표시 대상)
- ☐ 상호, 대표자명
- ☐ 사업자등록번호, (해당 시) 통신판매업 신고번호
- ☐ 사업장 주소, 고객 문의 연락처(이메일·전화)
- ☐ 토스페이먼츠 가맹 계약·심사 통과 (LIVE 키 발급 조건)

## B. 필수 페이지
- ☐ 이용약관 (서비스 성격: 엔터테인먼트, 결과의 한계, 금지 행위, 책임 범위)
- ☐ 개인정보 처리방침
  - 수집 항목: 생년월일·시간·성별은 **브라우저 안에서만 계산, 서버 미전송** / 서버 저장: 결과 id(무작위), 버전, 피드백(선택), 행동 이벤트, 주문 정보
  - 전화번호: 배틀 문자 보내기에만 쓰고 저장·전송하지 않음
  - 결제 정보: 카드 정보는 토스페이먼츠가 처리, 우리는 저장하지 않음 (payment_key 참조값만)
  - 보관 기간, 파기 절차, 제3자 제공·위탁(토스페이먼츠, Supabase, Vercel) 고지
- ☐ 결제·취소·환불 정책
- ☐ 상품 제공 내용 안내 (아래 C)
- ☐ 위 페이지 링크를 결과 하단·결제 안내 창에 연결

## C. 상품 정의 (현재 구현 기준)
| 상품 | 가격 | 제공 내용 (FREE 와의 차이) |
|---|---|---|
| 재물 심층 리포트 | 2,900원 | 나의 패턴 요약, WHY(근거별 기본+심화 설명), HOW(근거별 실천 3가지), 반전 포인트 심층(해당 시), 실천 체크리스트 5개 |
| 연애 심층 리포트 | 2,900원 | 같은 구성, 연애 영역 근거 |
| 직업·사업 심층 리포트 | 2,900원 | 같은 구성, 직업+사업 영역 근거 |

- ☑ FREE = WHAT, PREMIUM = WHY + HOW 구조 (서버 전용 문구, FREE 미리보기 1줄과 다른 심화 내용, 테스트로 확인)
- ☑ WHEN(시기)은 대운·세운 엔진 전이라 **판매 내용에 포함하지 않음** (리포트에 "포함되지 않음" 명시)
- ☐ 실제 구매자 관점에서 2,900원 가치가 있는지 사용자 검토 (리포트 샘플 확인)
- ☐ 가격 표시 "Beta 테스트 가격" 문구를 실제 판매 가격 표시로 바꿀지 결정

## D. 디지털 콘텐츠 제공 시점·환불
- ◐ 제공 시점: 결제 후 명시적 리포트 열기 → DB 최초 제공 기록 → 본문 반환 (코드·로컬 검사·실제 DB 구조/권한 확인 완료, Preview 동작·약관 검토 대기)
- ☐ 디지털 콘텐츠 청약철회 제한 사유를 적용할지, 적용 시 결제 전 고지·동의 절차 (법률 확인 필요)
- ◐ 환불 처리 절차: 미열람 고객 취소·열람 예외 관리자 TEST 도구 구현, 실제 Toss TEST·운영 검증 대기
- ☐ 결제 오류·중복 결제 시 대응 절차와 응답 기한

## E. 구매 복구 (LIVE 전 필수)
- ☑ 같은 기기: 저장된 구매 기록으로 다시 보기
- ☑ 다른 기기: 같은 생년월일·시간 재입력 + 구매 코드
- ◐ 구매 코드 분실 시: 영수증 기반 관리자 확인 → TEST 코드 재발급 도구 구현, 실제 운영 검증·LIVE 지원 대기
- ◐ 구매 코드 무차별 대입 대비 DB 속도 제한 구현 및 실제 Supabase 구조/권한 확인 완료, Preview 동작 검증 대기
- ☐ 고객 문의 창구 운영

## F. 기술 (TEST → LIVE)
- ☑ 서버 가격 결정, 금액·상품 변조 차단, 멱등 승인, PAID 덮어쓰기 방지 (단위 테스트)
- ☐ 토스 TEST 키로 실제 결제창 결제 성공·취소·실패 확인
- ☐ TEST 결제 후 Supabase orders 상태 확인 (PAID / CANCELLED / FAILED)
- ☐ TEST 환경 환불(취소) 확인 → REFUNDED
- ☐ iPhone Safari·Android Chrome 실기기 결제창 확인
- ☐ 토스 웹훅(결제 상태 변경 알림) 도입 여부 결정
- ☐ LIVE 키 발급 후 `PALJA_ALLOW_LIVE_PAYMENTS=yes` 설정은 **사용자 최종 승인 후에만**

## G. 운영
- ☐ 결제·환불 로그 확인 방법 (Supabase SQL)
- ☐ 매출 정산·세금 신고 방식 확인
- ☐ 장애 시 결제 기능 끄는 방법: `PALJA_PAYMENTS_MODE=off` 후 재배포
