# Premium 열람·환불 정책 설계 (Phase 2)

상태: 설계 확정 / 구현·법률 최종문구 검토 전

## 목표
결제 직후 Premium 전체 리포트를 읽고 곧바로 단순 변심 환불을 요청하는 악용을 줄이되, 결제 오류·중복 결제·콘텐츠 미제공·법령상 필요한 예외까지 막지 않는다.

## 핵심 원칙
1. 3분을 법적 환불 마감시간으로 사용하지 않는다.
2. 서버가 Premium 본문을 실제 반환하는 순간을 content_opened_at 최초 제공 시각으로 기록한다.
3. content_opened_at이 비어 있는 결제는 사용자에게 쉬운 구매취소 UX를 제공하는 방향으로 설계한다.
4. content_opened_at이 있으면 단순 변심 취소는 제한될 수 있음을 사전에 명확히 안내한다.
5. 오류/중복결제/미제공/표시·계약과 다른 제공 등 정당한 예외는 별도 고객지원·관리자 환불 경로로 처리한다.
6. 최종 약관·버튼 문구는 LIVE 전에 대한민국 전자상거래/디지털콘텐츠 관련 요건을 다시 확인한다.

## 사용자 흐름
PAID → 결제 완료 화면 → [구매 취소] 또는 [리포트 열기] → 리포트 열기 전 즉시 제공/청약철회 제한 가능성 안내 및 필요한 동의 → 서버가 entitlement 재검증 → 서버가 최초 제공 시각 기록 → Premium 본문 반환 → 이후 재열람은 같은 최초 제공 시각 유지

## 3분의 사용 방법
3분은 환불권 자체를 없애는 기준이 아니라 편의 UX로만 검토한다. 예: 결제 후 3분 동안 아직 미열람이면 결제 완료 화면에서 '바로 구매 취소'를 눈에 잘 띄게 제공. 3분이 지나도 법령/정책상 필요한 권리를 임의로 없애지 않는다.

## 악용 방지
- 브라우저 시각이 아니라 서버/DB 시각을 기준으로 한다.
- successUrl 도착만으로 열람 처리하지 않는다.
- Premium 본문을 반환하기 직전에 서버가 PAID + 상품 + chart_key + 구매코드를 재검증한다.
- 최초 제공 시각은 한 번만 기록하고 재열람으로 덮어쓰지 않는다.
- REFUNDED 주문은 Premium 본문을 반환하지 않는다.
- 구매코드 복구 API에는 LIVE 전 rate limit을 추가한다.
- 환불 API는 고객 브라우저에 관리자 권한을 노출하지 않는다.

## 아직 하지 않은 것
- 실제 고객용 환불 버튼
- Toss TEST 취소 호출 검증
- content_opened_at API 기록
- rate limit
- 최종 법률 문구/약관
- LIVE 결제

위 항목은 테스트 없이 완료로 표시하지 않는다.
