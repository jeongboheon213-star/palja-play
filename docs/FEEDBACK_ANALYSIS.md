# 피드백 저장·분석 안내

이미 있는 결과 화면의 만족도·영역별 평가·공유 의향·한마디 입력과 Supabase `beta_feedback` 테이블을 사용한다. 새 저장 서비스를 구매할 필요는 없다. 공개 브라우저 키는 INSERT만 가능하고 타인 피드백을 읽거나 수정·삭제할 수 없다. 관리자는 Supabase에서 확인한다. 기존 SQL 적용을 중복 요청하지 않는다.

## 연결 확인 (사용자 전용 키 입력)

현재 결제 서버용 `SUPABASE_SECRET_KEY`와 피드백 공개 키는 서로 다르다. 최근 빌드 로그의 `supabase: 미설정`은 공개 피드백 연결이 미설정임을 뜻하며 결제 서버 DB 상태를 뜻하지 않는다.

1. Supabase API Keys에서 공개 Publishable Key만 복사한다. Secret Key를 사용하지 않는다.
2. Vercel 환경 변수 `PALJA_SUPABASE_ANON_KEY`에 공개 키를 Preview 작업 브랜치에만 저장한다. 기존 `SUPABASE_URL`을 그대로 사용한다.
3. Preview 재배포 후 피드백 한 건을 제출하고 Supabase Table Editor의 `beta_feedback`에서 저장 여부를 확인한다. 키나 피드백 원문을 채팅으로 보내지 않는다.
4. 운영 공개와 광고 적용 전 별도로 Production 설정 및 테스트 자료 처리 정책을 결정한다. Preview도 현재 source=production으로 저장되므로 테스트 자료와 운영 자료를 섞어 분석하지 않는다.

## 분석 및 개선

`docs/feedback-analysis.sql`은 관리자 SQL Editor에서 읽기만 하는 월별 만족도, 안 맞은 영역, 해석 버전별 집계다. 원문은 출력하지 않는다. 작은 표본은 방향 참고로만 사용하고 충분한 응답 수가 쌓이면 반복되는 불만을 검토 → 개선 가설 → Preview 수정 → 검증 → 이전 버전과 비교 순서로 진행한다. 사주 계산 규칙을 만족도만으로 자동 변경하지 않는다.

피드백 원문에 개인정보가 포함될 수 있으므로 생년월일·연락처·구매 코드·결제 키 입력 금지 안내를 추가했다. 이 안내가 모든 개인정보 입력을 기술적으로 막는 것은 아니다. 원문 검토는 관리자만 하고 보관 기간 및 삭제 정책은 운영 전 결정한다. 집계 결과만 공유하면 이후 이 채팅에서도 분석과 개선 작업을 이어갈 수 있다. 정기 자동 분석은 아직 설정하지 않았다.
